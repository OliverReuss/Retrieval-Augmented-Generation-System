Rolle: Du bist ein Python-Entwickler auf Anfänger-Niveau. Du schreibst Code, der funktioniert und gut lesbar ist, aber du nutzt keine komplexen Konzepte wie, Dekoratoren, asynchrone Programmierung oder komplexe Design-Patterns.

Aufgabe: Implementiere eine RAG-Pipeline basierend auf den folgenden Anforderungen für ein AOK-Projekt.

Wichtige Anweisungen für den "Anfänger-Stil":

Struktur: Teile die Pipeline nach Bestandteilen in einzelne Dateien mit Klassen und Methoden auf. Erstelle jeweils eine Datei für: Web Scraping, Chunking, Emebdding, Retrieval, Generation, Evaluation. Alle Konfigurationsparameter sollen über eine config-Datei gesteurt werden und die Pipeline über die main.py gestartet werden.

Library-Nutzung: Nutze langchain immer wo es sinnvoll ist.

Web-Scraping: nutze Scrapy und ggf. CSS-Selektoren, um den Text der Seite ohne Navigtionselemente und anderem HTML zu holen. Keine komplexen Logiken, außer es ist absolut nötig. Erfasse nur URLs die "aok.de" beeinhalten und erfasse basierend von der als Einstiegspunkt angegebenen URLs bis zu einer definierten Tiefe alle Verlinkten Seiten. Schließe URLs aus, wenn diese Begriffe darin vorkommen: ["nordwest", "bw", "bayern", "bremen", "hessen", "nordost", "plus", "niedersachsen", "rps", "rh", "gp", "fk", "fm", "pp", "magazin", "datenschutzerklaerung", "karriere"]. Halte die Richtlininen der robots.txt ein. Speichere als JSON für die Weiterverarbeitung im Chunking.

Chunking: nutze Recursive Character Text Splitting nach Möglichkeit mit einer existierenden Library und lass den Nutzer die Länge und den Overlap bestimmen. Speichere als JSON für die Weiterverarbeitung im Embedding.

Retrieval: lege eine Vektordatenbank mit ChromaDB an. Nutze HNSW mit Cosinus-Ähnlichkeit. Und lasse den Nutzer top_k und hnsw_M definieren. Entferne bei einer Suchanfrage durch den Nutzer potenziell schädlichen Input durch regex-Erkennung und entferen Füllwörter, die in stop_words.txt definiert sind. Die Suchergebnissen sollen mittels eines Cross Encodes einem Relevance Reranking unterzogen werden.

Embedding: nutze ein Embedding-Modell, dass Dense-Embeddings erstellt. Speichere und lade das Modell lokal. Nutze falls sinnvoll Batchverarbeitung um das Embedding zu beschleunigen. Speichere das Embedding in der Vektordatenbank.

Generation: die Nutzereingabe soll mit den Suchergebnissen kombiniert werden und zur Antwortgenerierung an das LLM gesendet werden. Der Nutzer soll die URL des LLM defnineren können und den API-Key dazu angeben. Ebenso das Modell über einen Paramter. Außerdem die Parameter temperature, max_tokens, top_p, frequency_penalty und seed. Ebensol soll der Systempromt des LLM definiert werden können.

Evaluation: nutze RAGAS als Framework für die Evaluation. Die Evaluation erfolgt mittels einer Liste von Testfällen im JSON-Format im Format: "type, prompt, truth, source". Führe für jeden Testfall eine reale Nutzung des System durch und erstelle speichere die Ergebnisse im Format: "index, type, prompt, truth, source, context, sources, response, metriken". Füge alle konfigurierbaren Parameter in die Ergebnis-JSON ein, damit man die Konfiguration nachvollziehen kann. Erstelle für jede Metrik einen Gesamtdurchschnitt für alle Testfälle. Bewerte folgende Metriken:

- web scraping -> wird nur einmal zu Beginn des Ergebnis-Datei angeben
    - webscraping_elements_total: Anazhl der erstellten Elemente
    - webscraping_elements_with_text: Anzahl der nicht-leeren Texte
    - webscraping_extraction_success_rate: Anteil der Elemente mit Text
    - webscraping_duplicate_rate_by_text: Anteil von Einträgen mit gleichem Text
    - webscraping_average_text_length: durchschnittliche Länge der Texte

- retrieval
    - context_entity_recall: werden bestimmte Begriffe in der truth vorkommen im context gefunden?
    - context_precision: wie relevant sind die gefundenen Informationen im context, um truth abzudecken?
    - context_recall: wie vollständig sind die gefundenen Informationen im context, um truth abzudecken?

- generation
    - answer_correctness: Kombination aus faktischer Übereinstimmung und semantischer Ähnlichkeit zwischen response/truth
    - answer_relevancy: beantwortet die response den prompt?
    - answer_similarity: sematische Nähe der embeddings von response/truth
    - summarization_score: wie gut fasst die response den context zusammen?
    - faithfulness: basiert die response auf dem context oder gibt es Halluzinationen?
    - ece_score: misst Calibration (Übereinstimmung zwischen Confidence und Accuracy)
    - brier_score: bewertet Gesamtgenauigkeit der Wahrscheinlichkeitsvorhersagen, einschließlich Calibration und Discrimination
    - discrimination: misst Streuung der Wahrscheinlichkeiten, die das Modell den Vorhersagen zuordnet

Kommentare: Schreibe viele deutsche Kommentare, die erklären, was die Zeile gerade macht (typisch für Lernende).

Fehlerbehandlung: Nutze einfache if/else Abfragen statt komplexer try/except Blöcke, es sei denn, es geht um die Netzwerkverbindung.

Projekt-Details:

Ziel: Das Ergebnis soll so aussehen, als hätte ein motivierter Student das Projekt mit Hilfe von Tutorials Schritt für Schritt zusammengebaut, ohne bereits ein Software-Architekt zu sein. Vermeide "eleganten" oder "verkürzten" Code.
